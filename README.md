# Ticketwise — Cloud-Based Intelligent Support Ticket Classification and Priority Prediction

Ticketwise is an educational NLP web application that predicts a support ticket's category and urgency from its text. It combines a FastAPI REST API, scikit-learn models, and a responsive single-page dashboard with a warm paper-and-sunset visual theme.

> **Data note:** This project trains on generated synthetic examples, not real customer records. Its metrics are evaluation results on synthetic data and should not be interpreted as real-world performance guarantees.

## Features

- Predict one of six categories: Billing, Technical Issue, Account Access, Feature Request, Security, or Service Outage.
- Predict priority: low, medium, or high.
- Show confidence scores and flag low-confidence predictions for human review.
- Surface weighted text keywords as lightweight prediction context.
- Save corrected labels locally and retrain using submitted feedback.
- View holdout accuracy and macro-F1 metrics for the synthetic evaluation dataset.
- FastAPI API documentation at `/docs`.
- No MySQL, Docker, or external API key required.

## Technology

- Python 3.10+
- FastAPI and Uvicorn
- scikit-learn: TF-IDF + Logistic Regression
- HTML, CSS, and JavaScript
- pytest and FastAPI TestClient

## Run on Windows

Open PowerShell or the VS Code terminal in this project directory.

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
uvicorn app.main:app --reload
```

If PowerShell blocks activation, run `.\.venv\Scripts\python.exe -m pip install -r requirements.txt` and then `.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload`.

Open <http://127.0.0.1:8000>. API documentation: <http://127.0.0.1:8000/docs>.

The models train on startup, which may take a few seconds.

## Run tests

In a second terminal, with the virtual environment active:

```powershell
pytest -q
```

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/health` | API and model status |
| GET | `/api/categories` | Available category and priority labels |
| GET | `/api/metrics` | Synthetic holdout evaluation metrics |
| POST | `/api/predict` | Predict category, priority, confidence, and keywords |
| POST | `/api/feedback` | Save corrected labels locally |
| POST | `/api/retrain` | Retrain using generated data plus saved feedback |

Example prediction request:

```json
{
  "text": "Our team cannot sign in and password reset emails never arrive."
}
```

## How it works

1. Synthetic labeled ticket examples are generated by `app/data.py`.
2. TF-IDF transforms text into word and phrase features.
3. Separate Logistic Regression classifiers predict category and priority.
4. Confidence values are returned; low confidence triggers a review suggestion.
5. Corrections are saved to `app/feedback.json` and included when `/api/retrain` is called.

## Important limitations

- Synthetic examples are intentionally small and patterned. A high score on this dataset does not prove performance on real support tickets.
- Confidence scores are model probabilities, not guaranteed probabilities of correctness.
- Keyword display is a simple text-feature aid, not a full causal explanation.
- Feedback storage is a local JSON file; this is not designed for multi-user or production concurrency.
- There is no authentication, cloud deployment, or access-control layer. Do not expose the demo API publicly or enter sensitive personal data.
- “Cloud-based” describes the project direction and intended use case; the included version runs locally. A real cloud deployment would need hosting, security, monitoring, and data governance.

## Suggested next steps

- Collect a permissioned, anonymized, representative dataset.
- Compare models with stratified cross-validation and per-class precision/recall.
- Calibrate confidence thresholds using validation data.
- Add authentication and durable database storage before multi-user deployment.
- Deploy behind HTTPS with rate limits and logging.
